# 岗位搜索策略与本次优化

核验日期：2026-11-10。适用于 v1.0.1，相关功能已包含在安装包和便携包中，见[发行验证记录](windows-release-1.0.1.md)。搜索策略调研与功能验证仅查询公开资料并运行本地模拟测试，没有登录招聘账号、调用真实评分服务或执行投递。

## 调研结论

| 建议 | 一手资料依据 | 在本项目中的用法 |
| --- | --- | --- |
| 同类工作尝试不同岗位名称 | Indeed 建议增加相关岗位词；UC San Diego 指出相近职责可能使用不同职称。[S1][S2] | 用户明确输入多个备选词，程序逐词搜索并合并结果 |
| 用技能词补充岗位名称 | UC San Diego 建议尝试技能名称检索。[S2] | 如将 RAG、LangChain 作为补充搜索词，仍按简历和完整 JD 评估 |
| 搜索后按条件收窄 | Indeed 列举薪资、工作类型、地点和发布日期等筛选，且说明可用项随地区与搜索变化。[S1] | 使用当前平台已适配的筛选；不要把 BOSS 参数传给其他平台 |
| 零结果时检查条件是否过窄 | Indeed 建议改用较宽泛关键词、减少筛选或调整地点。[S3] | 先查看各词搜索统计；用户自行调整非必要条件，程序不会自动放宽城市或硬要求 |
| 用官方职位提醒跟进新增岗位 | Indeed 支持按搜索条件创建提醒，并调整关键词、地点和每日或每周频率。[S4] | 属于人工使用建议；本项目尚未接入各平台职位提醒 |
| 补充目标公司的官方招聘页面 | UC San Diego 建议列出目标公司并访问其招聘页面。[S2] | 作为平台检索之外的人工渠道；本次没有新增企业官网采集器 |

以上是搜索方法参考，不证明 BOSS、智联或猎聘使用相同的匹配算法、语法或推荐规则，也不保证提高实际面试率。

### 语法核验边界

- Indeed 当前打开的官方帮助页明确列出 `title:`、引号、减号排除和 `company:` 等用法。[S1] 这些属于其平台能力，本次不移植到国内平台。
- 前程无忧官方旧帮助页的搜索索引片段提到空格或逗号组合多关键词，但本次打开正文超时，不能用它确认当前网站行为。[S5] 招聘方的简历搜索帮助也不能代替求职方岗位搜索说明。
- 本次对 BOSS、智联的官方域名检索未找到足以核验统一布尔语法的求职帮助文档。当前实现只拆分用户明确输入的备选词，不解析 `AND`、`OR`、`NOT`，也不向平台附加这些运算符。

## 已实现

### 多个关键词分别搜索

在“求职设置 → 简历与搜索 → 搜索关键词”输入，例如：

```text
AI应用开发；大模型应用；LLM应用开发；RAG；LangChain
```

这是 AI 应用方向的示例词组，不是经过真实招聘数据比较后的最佳组合。建议先选择符合本人方向的少量词，再根据结果调整。

- 中文或英文逗号、分号用于分隔；解析器也接受换行。当前桌面输入框仍为单行。
- `Python API` 保持为一个查询词，词内连续空白压缩成一个空格。`C++`、`C#` 和 `/` 不会被拆分。
- 大小写和多余空白相同的词只查一次，保留首次出现的写法及顺序。
- 留空继续使用现有平台推荐模式；只有分隔符会提示错误，唯一关键词不能超过 50 个。
- BOSS 启动搜索页、智联登录检查页使用第一个解析后的关键词；后续各词走现有逐词查询流程。
- 搜索词应用于本轮匹配上下文，已有岗位画像的评分要求和阈值保留，不改写已存在的画像文件。

本轮各词共享原有请求预算，轮流获取结果，并沿用跨查询岗位 ID 去重。既有“AI 评估目标”和“请求预算”含义不变，达到目标可提前结束。本轮没有增加请求上限；代码中既有的“安全上限”仅是本地限制，不是平台认可的安全频率。

### 重复整页停止

公共检索流程按关键词分别保存整页岗位 ID 集合。同一关键词连续两次返回此前出现过的完整集合时，停止继续请求该词，并让尚可搜索的其他关键词继续。忽略排列顺序，出现新的整页集合则重置连续计数。

例如 `A → A → A` 在第三页结束；`A → A → B` 不会在第三页结束。A、B 表示整页 ID 集合。

以下情况不会单独触发该规则：

- 第一页全部属于历史已处理岗位；后续新页仍可继续。
- 不同关键词返回相同岗位；各关键词独立判断是否重复。
- 页面之间仅部分岗位重合。
- 页面存在缺失岗位 ID，无法完整比较。

平台适配器已有的更严格页面检查继续生效，可能更早停止该平台。平台访问限制或中断仍直接上抛，不切换同一平台的其他关键词继续尝试。猎聘自动化保持暂停。

### 每词搜索统计

正常结束时日志输出每个词的请求数、列表条目、词内唯一岗位、首次入队数量和停止原因。中途发生平台限制或异常时，正常结束统计可能不输出，应先查看限制或异常日志。

| 字段 | 口径 |
| --- | --- |
| 请求 | 该词发起列表查询的次数，包括失败或空页请求 |
| 列表条目 | 成功读取的非空列表条目累计，含重复岗位 |
| 词内唯一岗位 | 该词本轮返回过的不同非空岗位 ID 数量，含历史岗位和被过滤岗位 |
| 首次入队 | 通过列表筛选、由该词首次加入本轮候选队列的岗位数，跨词去重 |
| 停止原因 | 空页、连续重复页、查询失败、达到评估目标、每日上限或请求预算用尽 |

“首次入队”不是 AI 达标数量、投递量或面试量。两个词搜到同一岗位时，首次入队归先搜到的词，因此不能仅按它判断后一个词无用。候选仍在合并队列时会保留多个搜索来源；处理完成后的后续来源不会追写旧结果。本次没有按词自动调权或删除查询。

## 后续适合优化的方向

1. 按平台分别验证发布日期、截止日期和排序能力，再增加新岗位优先；字段未知时保留未知，不将抓取时间当发布日期。
2. 增加用户可确认的关键词建议，依据真实 JD 中的岗位称呼生成候选词，确认后再加入搜索。
3. 累积每词的 AI 达标数与人工保留数，并明确跨词重复归因，再考虑搜索预算分配。

这些是待验证方案，本次未实现。
