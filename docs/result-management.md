# 结果记录管理

## 使用方法

1. 在“投递结果”按状态、岗位/公司/平台关键词、分数区间或待复核状态筛选。
2. 勾选“选择”列，或点击“全选本页”。顶部显示已选数量，可用“取消选择”清空。
3. 点击“删除所选”，确认后删除勾选记录；行内“删除”列位于表格最右侧，点击垃圾桶可直接删除单个岗位。
4. 每页最多显示 200 项，用“上一页 / 下一页”浏览全部筛选结果。列排序作用于当前页；排序保持勾选对应的岗位，切换筛选、翻页、刷新则清空勾选。

## 删除范围与备份

- 列表把同一岗位的历史合并显示，删除有 ID 的岗位会清理 CSV 中相同 `encryptJobId` 的全部历史。跨平台岗位继续使用现有的统一岗位标识。
- 无岗位 ID 的记录按完整 CSV 字段内容和勾选数量匹配，不会把其他缺少 ID 的记录一并删除。完全相同的无 ID 记录按所选数量删除。
- 删除前在当前结果文件同目录生成原字节备份，名称如 `deliver_results.csv.delete-20261110-153000-随机标识.bak`，备份路径同时记入运行日志。
- 写回保留原表头、自定义列及未删除记录的字段内容；删除最后一条后保留 CSV 表头。使用同目录临时文件写入后替换，写入失败时保留原文件并清理临时文件。
- 删除前核对列表加载时的文件指纹。文件发生变化时停止删除，刷新后重新选择；任务运行时不能删除，以避免与结果写入冲突。
- 恢复备份时先结束任务并关闭占用 CSV 的程序，将目标备份复制回配置中的结果文件路径，再刷新列表。恢复整个备份会回到该次删除前的全部历史，恢复前应另外保留当前结果文件。

## 对后续任务的影响

这里只删除本地结果历史，不撤回招聘平台上的投递或消息，也不修改每日投递跟踪文件和计数。历史结果参与跨次任务去重，删除后岗位可能在后续任务中再次进入处理。对“投递待核对”等记录，先核对官方投递记录再决定是否删除。

该功能已包含在 v1.0.1 中，安装包、便携包及验证范围见[发行验证](windows-release-1.0.1.md)。结果管理验证使用临时 CSV 和模拟岗位，不涉及真实招聘账号、AI 调用或实际投递。
